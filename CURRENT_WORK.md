# Current work

**Feature:** F25 – Install without a toolchain
**Status:** in progress
**Started:** 2026-08-25

## Goal

Running KassenKnoten stops requiring a build. A multi-architecture image is published to
GHCR on every tag, `docker compose up -d` pulls it, and the two setup secrets are
generated by the image itself. What a self-hoster downloads becomes two files —
`docker-compose.yml` and `.env.example` — instead of a source tree, a Node toolchain and
a five-minute build.

## Scope

- In: a workflow publishing `ghcr.io/jankln/kassenknoten` for amd64 and arm64, a compose
  file that pulls rather than builds, a build override for working from source, the setup
  scripts carried inside the image, and the documentation rewritten around all of it.
- Out: Helm charts, an unRAID/Portainer template, automatic updates, signing the image.

## Decisions

- **The image carries its own setup scripts.** With a prebuilt image and no checkout there
  is otherwise no way to produce an argon2id hash or a TOTP secret, and "just pull the
  image" would be a promise that breaks at step two. Node 22 runs TypeScript directly, so
  `scripts/hash-password.ts` and `scripts/totp-secret.ts` go in as they are — the same
  files the repository tests, not a second copy that can drift.
- **Compose pulls; building is the override.** `docker-compose.yml` names the published
  image and nothing else, and `docker-compose.build.yml` layers the build back on for
  anyone working from source. A compose file that carries both silently builds when the
  image happens to be missing, which is the one behaviour neither audience wants.
- **`scripts/pack-release.sh` goes away.** It was written yesterday for a world where the
  release had to ship source. With a published image its bundle has no audience: the two
  files people actually need are attached to the release directly, and GitHub's own
  "Source code" archives already cover building from scratch. Keeping it would mean
  maintaining an artifact nobody downloads.
- **Native runners rather than QEMU.** ARM runners are free for public repositories, and
  emulating an arm64 Next.js build costs half an hour per release for the same bytes.

## Notes / decisions

- The first push to GHCR creates the package as private. It has to be made public once,
  and the release is not finished until a pull works without credentials.
- Verification has to start from an empty directory with no repository checkout, because
  that is the situation the whole feature exists to serve.
